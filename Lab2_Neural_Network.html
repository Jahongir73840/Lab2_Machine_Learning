1. Dataset¶

Each image has 8 x 8 pixels, so there are 64 input features. Pixel values are between 0 and 16. Dividing by 16 puts them in the range [0, 1]. A one-hot label has ten entries, with 1 at the correct digit and 0 elsewhere. Stratification keeps similar class proportions in the two sets.

2. Network design¶

64 inputs -> W neurons -> ReLU -> W neurons -> ReLU -> 10 outputs -> softmax

Parameter W = 16 W = 64
W1 (64, 16) (64, 64)
b1 (16,) (64,)
W2 (16, 16) (64, 64)
b2 (16,) (64,)
W3 (16, 10) (64, 10)
b3 (10,) (10,)

For a batch of m examples, the hidden activations have shape (m, W) and the output has shape (m, 10). Biases are added to every row. I interpret the manual's N(0, 0.01) as mean 0 and standard deviation 0.01 (normal(0, 0.01) in NumPy). Biases start at zero. ReLU is max(0, z), so it introduces nonlinearity.

In [3]:
def initialise(width, seed=42):
    rng = np.random.default_rng(seed)
    return {
        "W1": rng.normal(0, 0.01, (64, width)),
        "b1": np.zeros(width),
        "W2": rng.normal(0, 0.01, (width, width)),
        "b2": np.zeros(width),
        "W3": rng.normal(0, 0.01, (width, 10)),
        "b3": np.zeros(10),
    }

3. Forward pass and cross-entropy¶

The forward equations are:

$$Z_1=XW_1+b_1,\quad A_1=\mathrm{ReLU}(Z_1)$$ $$Z_2=A_1W_2+b_2,\quad A_2=\mathrm{ReLU}(Z_2)$$ $$Z_3=A_2W_3+b_3,\quad P=\mathrm{softmax}(Z_3)$$

Softmax changes the scores into probabilities: $$P_{ik}=\frac{e^{Z_{3,ik}}}{\sum_j e^{Z_{3,ij}}}.$$ I subtract each row's maximum before exponentiation to avoid overflow. This does not change softmax probabilities.

The average cross-entropy is $$L=-\frac{1}{m}\sum_i\sum_k Y_{ik}\log P_{ik}.$$ In the code I calculate log probabilities directly from the shifted scores. This avoids taking log(0). Before training, probabilities should be close to 0.1, so the loss should be close to -log(0.1) = 2.3026.

In [4]:
def forward(X_batch, params):
    Z1 = X_batch @ params["W1"] + params["b1"]
    A1 = np.maximum(0, Z1)
    Z2 = A1 @ params["W2"] + params["b2"]
    A2 = np.maximum(0, Z2)
    Z3 = A2 @ params["W3"] + params["b3"]

    shifted = Z3 - Z3.max(axis=1, keepdims=True)
    exp_scores = np.exp(shifted)
    P = exp_scores / exp_scores.sum(axis=1, keepdims=True)
    cache = (X_batch, Z1, A1, Z2, A2, Z3, P)
    return P, cache


def cross_entropy(scores, Y_batch):
    shifted = scores - scores.max(axis=1, keepdims=True)
    log_probs = shifted - np.log(np.exp(shifted).sum(axis=1, keepdims=True))
    return -np.mean(np.sum(Y_batch * log_probs, axis=1))

4. Backpropagation: chain rule¶

For one example, softmax has derivative $$\frac{\partial P_k}{\partial z_j}=P_k(\delta_{kj}-P_j).$$ Combining this with cross-entropy gives $$\frac{\partial L_i}{\partial z_j} =-\sum_k\frac{Y_k}{P_k}P_k(\delta_{kj}-P_j)=P_j-Y_j.$$ The labels sum to one. Averaging over a batch adds a factor 1/m.

Start at the output and work backwards. Here D means the derivative of the loss with respect to an intermediate value, and * is elementwise multiplication.

$$D_3=(P-Y)/m$$ $$\frac{\partial L}{\partial W_3}=A_2^T D_3,\quad \frac{\partial L}{\partial b_3}=\sum_i D_{3,i}$$ $$D_2=(D_3W_3^T)*\mathbf{1}[Z_2>0]$$ $$\frac{\partial L}{\partial W_2}=A_1^T D_2,\quad \frac{\partial L}{\partial b_2}=\sum_i D_{2,i}$$ $$D_1=(D_2W_2^T)*\mathbf{1}[Z_1>0]$$ $$\frac{\partial L}{\partial W_1}=X^T D_1,\quad \frac{\partial L}{\partial b_1}=\sum_i D_{1,i}$$

ReLU passes the gradient where its input is positive, and gives zero for negative inputs. I use derivative zero at exactly zero as well. The weight gradients have the same shapes as their corresponding weights. Gradient descent updates each parameter using theta = theta - learning_rate * gradient.

In [5]:
def backward(Y_batch, params, cache):
    X_batch, Z1, A1, Z2, A2, Z3, P = cache
    m = len(X_batch)

    D3 = (P - Y_batch) / m
    dW3 = A2.T @ D3
    db3 = D3.sum(axis=0)

    D2 = (D3 @ params["W3"].T) * (Z2 > 0)
    dW2 = A1.T @ D2
    db2 = D2.sum(axis=0)

    D1 = (D2 @ params["W2"].T) * (Z1 > 0)
    dW1 = X_batch.T @ D1
    db1 = D1.sum(axis=0)

    return {"W1": dW1, "b1": db1, "W2": dW2,
            "b2": db2, "W3": dW3, "b3": db3}

5. Numerical gradient check¶

I choose 10 random weight entries without replacement for each width. No training or parameter updates are done during this check. For each selected weight, the central difference is $$g_{num}=\frac{L(w+\epsilon)-L(w-\epsilon)}{2\epsilon},\quad\epsilon=10^{-5}.$$ I compare it with backpropagation using $$\mathrm{relative\ error}=\frac{|g_{num}-g_{analytical}|} {\max(10^{-12}, |g_{num}|+|g_{analytical}|)}.$$ The requirement is at least 9 out of 10 errors below 1e-6. ReLU has a corner at zero, so the numerical check can be affected if a perturbation changes which neurons are active.

In [6]:
def gradient_check(width):
    params = initialise(width)
    X_small, Y_small = X_train[:8], Y_train[:8]
    _, cache = forward(X_small, params)
    grads = backward(Y_small, params, cache)
    for name in params:
        assert grads[name].shape == params[name].shape

    names = ["W1", "W2", "W3"]
    sizes = [params[name].size for name in names]
    rng = np.random.default_rng(42)
    chosen = rng.choice(sum(sizes), size=10, replace=False)
    epsilon = 1e-5
    rows = []

    for flat_index in chosen:
        for name, size in zip(names, sizes):
            if flat_index < size:
                break
            flat_index -= size
        index = np.unravel_index(flat_index, params[name].shape)
        original = params[name][index]

        params[name][index] = original + epsilon
        _, plus_cache = forward(X_small, params)
        plus_loss = cross_entropy(plus_cache[5], Y_small)

        params[name][index] = original - epsilon
        _, minus_cache = forward(X_small, params)
        minus_loss = cross_entropy(minus_cache[5], Y_small)
        params[name][index] = original

        numerical = (plus_loss - minus_loss) / (2 * epsilon)
        analytical = grads[name][index]
        error = abs(numerical - analytical) / max(
            1e-12, abs(numerical) + abs(analytical)
        )
        passed = bool(error < 1e-6)
        rows.append({"width": width, "weight": name,
                     "row": int(index[0]), "column": int(index[1]),
                     "analytical": float(analytical), "numerical": float(numerical),
                     "relative_error": float(error), "passed": passed})
        print(f"{name}{tuple(int(i) for i in index)}: analytical={analytical:.8e}, "
              f"numerical={numerical:.8e}, error={error:.2e}, "
              f"{'PASS' if passed else 'FAIL'}")

    passed_count = sum(row["passed"] for row in rows)
    print(f"W={width}: {passed_count}/10 passed\n")
    return rows, passed_count

6. Training and evaluation¶

I train all six combinations for 50 epochs with batches of 32. Each epoch shuffles the training examples. The last, smaller batch is included too. For each width, all learning rates start with the same weights and use the same shuffle sequence, making comparison easier.

Loss is recorded on the whole training set after each epoch. The test set is used only for the final evaluation, not for gradient updates. Prediction means taking the digit with the highest softmax probability.

In [7]:
def train(width, learning_rate):
    params = initialise(width)
    rng = np.random.default_rng(123)
    history = []
    start = perf_counter()

    for epoch in range(1, 51):
        order = rng.permutation(len(X_train))
        for first in range(0, len(order), 32):
            batch = order[first:first + 32]
            _, cache = forward(X_train[batch], params)
            grads = backward(Y_train[batch], params, cache)
            for name in params:
                params[name] -= learning_rate * grads[name]

        P_train, cache = forward(X_train, params)
        loss = cross_entropy(cache[5], Y_train)
        accuracy = np.mean(P_train.argmax(axis=1) == y_train)
        assert np.isfinite(loss)
        history.append({"width": width, "learning_rate": learning_rate,
                        "epoch": epoch, "train_loss": float(loss),
                        "train_accuracy": float(accuracy)})
        print(f"W={width:2d}, lr={learning_rate:.3f}, epoch={epoch:02d}, "
              f"loss={loss:.4f}, train accuracy={accuracy:.4f}")

    elapsed = perf_counter() - start
    P_test, test_cache = forward(X_test, params)
    result = {"width": width, "learning_rate": learning_rate,
              "train_loss": history[-1]["train_loss"],
              "test_loss": float(cross_entropy(test_cache[5], Y_test)),
              "train_accuracy": history[-1]["train_accuracy"],
              "test_accuracy": float(np.mean(P_test.argmax(axis=1) == y_test)),
              "training_seconds": elapsed}
    return params, history, result

7. Forward and backward timing¶

I use a batch of 32 training examples and the trained model with lr = 0.1 for each width. After 10 warm-up runs, I measure 100 forward and 100 backward passes separately and report the medians in milliseconds. Backward timing uses a ready forward cache. It does not include another forward pass, loss evaluation, or parameter updates. These are local CPU measurements, so results may vary on another computer.

In [9]:
timing_rows = []
timing_samples = []
for width in [16, 64]:
    params = models[(width, 0.1)]
    X_batch, Y_batch = X_train[:32], Y_train[:32]
    for _ in range(10):
        _, cache = forward(X_batch, params)
        backward(Y_batch, params, cache)

    forward_times, backward_times = [], []
    for run in range(100):
        start = perf_counter()
        _, cache = forward(X_batch, params)
        forward_ms = (perf_counter() - start) * 1000

        start = perf_counter()
        backward(Y_batch, params, cache)
        backward_ms = (perf_counter() - start) * 1000

        forward_times.append(forward_ms)
        backward_times.append(backward_ms)
        timing_samples.append({"width": width, "run": run + 1,
                               "forward_ms": forward_ms, "backward_ms": backward_ms})

    forward_median = float(np.median(forward_times))
    backward_median = float(np.median(backward_times))
    timing_rows.append({"width": width, "batch_size": 32, "runs": 100,
                        "forward_median_ms": forward_median,
                        "backward_median_ms": backward_median,
                        "backward_over_forward": backward_median / forward_median})
    print(f"W={width}: forward={forward_median:.4f} ms, "
          f"backward={backward_median:.4f} ms, "
          f"backward/forward={backward_median / forward_median:.2f}")

save_csv("timing.csv", timing_rows)
save_csv("timing_samples.csv", timing_samples)

W=16: forward=0.0232 ms, backward=0.0252 ms, backward/forward=1.09
W=64: forward=0.0361 ms, backward=0.0470 ms, backward/forward=1.30

The forward pass has three matrix multiplications. Backpropagation has five: three weight gradients and two multiplications to pass gradients to earlier hidden layers. It also applies ReLU masks and sums bias gradients. Therefore backward usually takes more time, although these small matrices also make function overhead and memory allocation noticeable. Increasing W makes the middle layer more expensive because it uses a W x W weight matrix. The number of multiplications alone does not predict the exact measured ratio.

Conclusion¶

In this run, the gradient check passed for 9/10 weights at W = 16 and 10/10 weights at W = 64, meeting the required threshold. The one failed entry had a small gradient (about -2.94e-6) and an absolute difference of about 1.5e-11. Subtracting nearly equal losses can cause this relative error. Several sampled gradients were zero because of inactive ReLU units or zero-valued inputs. This is a sampled check, not a proof for all parameters.

The best observed result was W = 64 and learning rate 0.1. Its training loss fell to 0.1883. With rates 0.001 and 0.01, loss stayed near 2.3026 and accuracy was around chance level. Small initial weights make the early hidden-layer gradients small, so these rates made little progress in 50 epochs.

At W = 16 and lr = 0.1, learning started late and the loss jumped on the last epoch. A constant large learning rate and mini-batch updates can make the loss fluctuate. I kept the final-epoch result as requested. W = 64 learned faster here, but one split and one seed do not establish that a wider network is always better.

Backpropagation was slower for both widths in the measured run. It needs more matrix multiplications than the forward pass. The timing table gives the actual medians; the exact values depend on the computer and its load. Comparing the six test results is part of the lab. For separate tuning, I would use a validation set and keep the test set for the final evaluation.
